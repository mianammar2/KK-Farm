# Prototype Gap Analysis (apps/kk-farm vs the SaaS direction)

**Date:** 2026-11-07 · Based on reading the source (migration, models, `Farm.php`, routes, tests). The app was **not run** (Docker was not running on the review machine), so behaviour is unverified here. Compared against [SAAS_PLAN.md](SAAS_PLAN.md), D-037, D-038, D-039 and the workbook analysis.

## Keep as is
| Item | Why |
|---|---|
| `animals.id` uuid, never the tag; farm number from a forward-only sequence | Matches D-004; ids are never reused |
| `rfid_tags` + `rfid_assignments` with `valid_from`/`valid_to` and a **partial unique index** (one open assignment per tag) | Exactly the tag-as-physical-object model; scan → animal lookup is cheap |
| Pedigree walk (`pedigree`, `sharedAncestors`) | Directly serves the breeding-research question (inbreeding checks) |
| `adg()` and weight records | Matches the workbook rule |
| Photo gallery tied to the animal id | Owner requirement D-020 |
| Module/role middleware, audit `activities`, 17 rule tests on PostgreSQL | Good base to extend |

## Change
| Gap | Detail | Action |
|---|---|---|
| **No tenancy** | No `org_id`/`farm_id` anywhere; `farm_number` is globally unique | D-037: add `org_id`, RLS, per-tenant uniqueness, tenant-scoped sequence |
| **Integer ids on history tables** | `animal_events`, `matings`, `kiddings`, `weight_records` use auto-increment ids | Move to client-generated UUIDv7 for idempotent offline sync (D-038) |
| **Mutable history** | `matings.status` is updated in place; history tables carry `updated_at`; no `supersedes_id` | Immutable rows + corrections; derive status |
| **`animal_events` is summary-only** | `type`, `summary`, `recorded_by` (string) | Add envelope: `source`, `device_id`, `recorded_at`, `recorded_by` as user id, typed refs, `attributes jsonb` |
| **State columns hand-set** | `animals.status`, `health_status`, `repro_state`, `pen_id` edited directly; no derived pen headcount | Derive from events; headcount per pen rebuildable (fixes the missing-goat feed problem) |
| **Single breed per animal** | `breed_id` only | Add breed composition or cross label (research by breed cross) |
| **Vocabularies hard-coded** | Strings in migration comments | Tenant-editable reference tables seeded from the workbook values |
| **Single-farm assumptions** | One shed, sheds/pens simple | Hierarchy Organization → Farm → Site → Pen |

## Add (missing from the prototype, present in the workbook)
Pregnancy checks as events · weaning · preventive care (vaccine, deworming, next due) · treatments with **separate meat and milk clear dates** and a computed lockout · medicine stock and movements · feed items and stock movements · feeding compliance · body condition score · lactation/milk records (if confirmed) · tasks generated by rules · alerts engine.

## Add (new for the direction)
Tenants, memberships and scoped roles · devices and device auth (C72 guns, gateways) · sensor registry and readings (ammonia, EKM energy, temperature, silo weight) · camera/photo ingestion · rule engine producing alerts and tasks · pen census (scanned set vs expected set) · import/export of the workbook layout · research views (litter size, survival, ADG by breed/sire/dam, disease incidence).

## Not reviewed yet
Controllers and React pages in depth, `DESIGN.md`, the e2e test, styling. The prototype's synthetic seed data is KK Farm-like (118 goats); real data must never be committed.

## Suggested first slices (each shippable)
1. Tenancy + RLS spike and tests (one table, then all).
2. Event envelope and migration of matings/kiddings/weights to immutable events, with derived pen headcount.
3. Treatments with meat/milk clear dates and lockout rule.
4. C72 scan spike (key codes, EPC read, single-tag mode).
5. Sensor ingestion skeleton with one adapter.
